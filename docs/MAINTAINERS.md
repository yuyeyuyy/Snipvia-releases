# 分发仓库维护

## 职责

私有工程负责源码、依赖、构建、功能测试、签名、公证与最终发行资产；本仓库负责公开安装包、更新说明、清单和文件校验。

不要把私有源码、工作目录、测试应用、内部报告、个人截图、凭据或 Apple 私钥加入本仓库 Git 历史。大文件放 GitHub Release 资产，不提交到 Git。

## 正式发行

1. 在私有工程完成版本更新、测试、受信签名、公证和平台验收。
2. 使用私有工程的 `pnpm release:publish --directory <verified目录> --notes <说明文件>` 检查发布计划；确认目录中的更新仓库为 `yuyeyuyy/Snipvia-releases`。
3. 在明确授权发布后，加 `--execute`。脚本创建草稿、上传白名单资产、核对 GitHub 资产哈希与大小，全部通过后发布为正式版本。不覆盖已发布资产。
4. 查看公开仓库的 Release 校验任务，并匿名检查版本接口、更新说明和下载文件。

私有工程的 `verification.json` 是本地发布门槛，不作为公开附件上传。它记录正式签名、公证验收和更新源；旧的无更新源报告不能作为新自动更新发行发布。

## GitHub Actions

`Release validation` 在公开仓库执行校验器测试，并可按已发布 Tag 下载文件进行清单校验。工作流只使用本公开仓库的只读 `GITHUB_TOKEN`，不需要访问私有工程或保存长期 Token。

Release 由发布凭据上传。跨仓库 Actions 发布若将来启用，需要仅授权本分发仓库的写入凭据，存放在私有工程 Secrets；不在客户端或本仓库中保存。当前本机发布直接复用 GitHub CLI 登录。

## 历史版本迁移

v0.2.1 仅迁移原已发布的安装文件、两份安装说明、变更说明和校验文件。旧包的签名、功能与平台边界保留原说明，不重新标记为自动更新版。源仓库 Release 保留，迁移不删除历史。

本次云端搬运先核对原 SHA-256，再上传到现有草稿；仅使用原安装包的短时单文件下载地址，没有在公开仓库保存源码访问 Token。搬运完成后删除短时下载 Secret 和单次工作流。证据见[迁移清单](migration-v0.2.1.json)与[成功的搬运任务](https://github.com/yuyeyuyy/Snipvia-releases/actions/runs/38222206135)。
